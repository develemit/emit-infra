# Store Terraform state in Cloudflare R2
**Difficulty:** 3

## Goal
Create a dedicated R2 bucket for Terraform state before running `terraform init`,
write a `backend.tf` to the project's terraform directory, and pass the bucket
credentials as `-backend-config` flags so state is stored remotely from day one.

## Reason
`terraform.tfstate` currently lives on the developer's machine. If that machine
is lost or the file is accidentally deleted, the Hetzner server and DNS records
become unmanageable — Terraform can no longer reconcile or destroy them. Storing
state in Cloudflare R2 means any machine with the CF token can recover.

## Context
- `packages/core/src/r2.ts` has `resolveAccountId`, `ensureR2Bucket`,
  `createR2Token` — use these directly (no new dependencies).
- `packages/core/src/terraform.ts` — `runTerraform(cmd, args, cwd)` already
  accepts `args: string[]`. Pass `-backend-config` flags there.
- `apps/cli/src/commands/setup.ts` — the 5-or-6-step setup flow. The state
  bucket must be created **before** `terraform init` (step 3). Insert a new
  step 3 "Prepare remote state", shift current step 3 to step 4. Update `total`
  accordingly: add 1 to both the base (5→6) and R2-present (6→7) totals.
- The state bucket is always created (every project needs it), independent of
  whether `config.r2.buckets` or `config.postgres.backupBucket` are set.
- Bucket name convention: `{project-name}-tfstate`
- `TF_VAR_cloudflare_api_token` is already validated in pre-flight.

### Terraform S3 backend for R2

Write `terraform/backend.tf` (no credentials — those come via CLI flags):

```hcl
terraform {
  backend "s3" {
    bucket                      = "{name}-tfstate"
    key                         = "terraform.tfstate"
    region                      = "auto"
    endpoint                    = "https://{accountId}.r2.cloudflarestorage.com"
    skip_credentials_validation = true
    skip_metadata_api_check     = true
    skip_region_validation      = true
    force_path_style            = true
  }
}
```

Pass credentials to `terraform init` as:
```
terraform init \
  -input=false \
  -backend-config="access_key=<accessKeyId>" \
  -backend-config="secret_key=<secretAccessKey>"
```

`backend.tf` is safe to commit (no secrets). Add it to `terraform/.gitignore`
is unnecessary — it contains no credentials.

## Tasks

1. In `setup.ts`, before the Terraform step, add a new step:
   ```
   step(3, total, 'Preparing remote state bucket')
   const cfToken = process.env.TF_VAR_cloudflare_api_token!
   const stateAccountId = await resolveAccountId(cfToken)
   const stateBucket = `${config.name}-tfstate`
   await ensureR2Bucket(stateAccountId, stateBucket, cfToken)
   const stateToken = await createR2Token(stateAccountId, stateBucket, cfToken)
   ok(`State bucket ready: ${stateBucket}`)
   ```

2. Write `terraform/backend.tf` immediately after — interpolate `stateBucket`
   and `stateAccountId` into the template above. Use `writeFileSync`.

3. Change `total` from `hasBuckets || hasBackupBucket ? 6 : 5` to
   `hasBuckets || hasBackupBucket ? 7 : 6`. Renumber all subsequent steps
   (old step 3 → new step 4; old steps 4/5 → 5/6; old 5/6 → 6/7).

4. Change the `terraform init` call to pass the backend-config flags:
   ```ts
   await runTerraform('init', [
     '-input=false',
     `-backend-config=access_key=${stateToken.accessKeyId}`,
     `-backend-config=secret_key=${stateToken.secretAccessKey}`,
   ], tfDir)
   ```

5. In `init.ts`, add a comment to `buildTerraformRoot()` below the `terraform {}`
   block: `# backend.tf is generated by emit-infra setup (remote state via R2)`
   — so a developer knows not to create it manually.

6. Run `pnpm tsc --noEmit -p apps/cli/tsconfig.json` — confirm clean.
