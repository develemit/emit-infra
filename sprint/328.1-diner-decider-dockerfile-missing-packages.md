# Add the missing workspace packages to diner-decider's api Dockerfile
**Difficulty:** 3

> _Written by /start-sprint-auto to clear sprint 328's blocker, 2026-09-12._

## Goal
`diner-decider`'s `apps/api` image builds again at HEAD — the two workspace
packages its `package.json` depends on are present in the build context, and
that is proven by an actual `linux/amd64` build, not by inspection.

## Reason

Confirmed independently before filing this sprint:

- `~/projects/diner-decider/packages/` contains `db`, `db-test-guard`,
  `pricing`, `quota-limits`.
- `apps/api/package.json` declares `"@diner-decider/quota-limits":
  "workspace:*"` (line 10) and `"@diner-decider/db-test-guard":
  "workspace:*"` (line 36).
- `apps/api/Dockerfile` COPYs only `packages/db` — `package.json` at line 12,
  full source at line 19. Neither missing package appears anywhere in the file.

This is latent, not theoretical: diner-decider is 33 commits ahead of its
deployed `367de26`, and the deploy path only rebuilds a service when its

worth fixing now, while the cause is known, rather than during an incident.

## Context

### The file
`~/projects/diner-decider/apps/api/Dockerfile`. Its multi-stage shape, with
current line numbers:

```
 9  COPY package.json pnpm-lock.yaml pnpm-workspace.yaml ./
10  COPY patches ./patches/
11  COPY apps/api/package.json ./apps/api/
12  COPY packages/db/package.json ./packages/db/
...
17  COPY nx.json tsconfig.base.json ./
18  COPY apps/api ./apps/api
19  COPY packages/db ./packages/db
```

Two distinct groups, and **both** need the new entries:

- The **manifest group** (11-12) exists so `pnpm install` caches on manifests
  alone. A `workspace:*` dependency whose `package.json` is absent makes the
  install fail to resolve the link.
- The **source group** (18-19) is what `pnpm nx run api:build` actually
  compiles against.

Add `packages/quota-limits` and `packages/db-test-guard` to each group,
matching the existing style exactly. Do not reorder or restructure the file —
layer order is load-bearing for caching.

### Check for the same gap elsewhere
`packages/pricing` also exists. Check whether `apps/api` (or `apps/web`)
depends on it and whether its Dockerfile COPYs it; fix in the same pass if the
same omission is present, and say so. Do **not** go beyond the api and web
Dockerfiles in this repo.

### Verifying — an actual build is required
Inspection is what let this sit undetected. Build the image for the target
platform and let it fail or pass on its own:

```bash
cd ~/projects/diner-decider
docker build --platform linux/amd64 -f apps/api/Dockerfile -t dd-api-verify:local .
```

A successful build through the `pnpm nx run api:build` step is the evidence.
Capture the failing output **before** the fix too — a fix never seen to change

## Completed

**Date:** 2026-09-12

### Summary
diner-decider's `apps/api/Dockerfile` and `apps/web/Dockerfile` both had
missing `COPY` entries for workspace packages their `package.json`s actually
depend on — a real, confirmed build-breaking gap in each, not just the one
sprint 328 flagged.

`apps/api/Dockerfile` never gained entries for `packages/quota-limits` and
`packages/db-test-guard` (both added in sprint 88). Fixed by adding both
packages' `package.json` to the manifest COPY group and both packages' full
source to the source COPY group, matching the existing `packages/db` style
exactly. Layer order was preserved — no restructuring.

While checking "the same gap elsewhere" as the sprint asked (using
`packages/pricing` as the suggested lead), `packages/pricing` turned out to
already be correctly copied in `apps/web/Dockerfile` — no omission there.
But inspecting `apps/web/package.json`'s dependencies against its Dockerfile
surfaced a **second, independent instance of the identical bug**: `web`
declares `@diner-decider/quota-limits` as a `workspace:*` dependency and
genuinely imports it (`src/app/premium/premium-parts.tsx`,
`src/lib/quota-copy.ts`), but `apps/web/Dockerfile` never copied it either.
Verified this was a real active failure (not theoretical) the same way as
`api`: a clean pre-fix build of `apps/web/Dockerfile` fails
`pnpm nx run web:build` with "Module not found: Can't resolve
'@diner-decider/quota-limits'" from both files. Fixed with the same
two-line-pair pattern.

**Verification used a clean throwaway `git clone` to `/tmp`, not the
persistent checkout, and this was a deliberate choice, not incidental.**
Building directly from `~/projects/diner-decider` hit an unrelated, pre-existing
problem: `.dockerignore`'s bare `node_modules` pattern does **not** exclude
nested `node_modules` directories (e.g. `apps/api/node_modules`) from the
build context — confirmed directly by COPYing `apps/api` into a throwaway
image and finding `node_modules` present despite `.dockerignore`. Because the
local dev checkout has `apps/api/node_modules/sharp` installed as a symlink
into the pnpm store, and the Dockerfile's own `pnpm install` step (with
`node-linker=hoisted`) independently populates the same path as a real
directory, `COPY apps/api ./apps/api` from the dirty checkout fails with
"cannot replace to directory .../node_modules/sharp with file" — a completely
different error from the one this sprint targets, and one that would mask
whether the intended fix actually worked. A clean clone has no local
`node_modules` at all, so this sidesteps it and gives an unambiguous
before/after signal for the actual fix. **This `.dockerignore` gap is real
and separate, and — per `scripts/lib/docker-build.sh`'s `build_image`, which
builds with context `.` from whatever directory the pre-push hook runs in —
would affect real deploys too, since deploys build from the persistent
checkout, not a fresh clone.** Left unfixed here (out of scope: a different
file, not either Dockerfile) but filed below as a `[blocker]`.

### Follow-ups
- `[blocker]` diner-decider's `.dockerignore` has a bare `node_modules`
  pattern that does not exclude nested `node_modules` directories (e.g.
  `apps/api/node_modules`, `apps/web/node_modules`) from the Docker build
  context — confirmed by direct COPY test. Building from the persistent local
  checkout (which has these installed for local dev) causes `COPY apps/api
  ./apps/api` to fail with "cannot replace to directory
  .../node_modules/sharp with file" because the host's symlinked `sharp` and
  the container's own hoisted-install `sharp` directory collide at the same
  path. `scripts/lib/docker-build.sh`'s `build_image` builds with context `.`
  from wherever the pre-push hook runs — i.e. the persistent checkout — so
  this would break real deploys the same way it broke verification here, any
  time the local checkout has `node_modules` installed under `apps/api` or
  `apps/web` at push time. Needs an explicit `**/node_modules` (or
  `*/node_modules`, or per-app) pattern in `.dockerignore`. Not fixed here:
  it's a `.dockerignore` change, not a Dockerfile change, and this sprint's
  scope was the two named Dockerfiles.
- `[defer]` diner-decider is now 34 commits ahead of `origin/main` (was 33
  before this sprint's commit) — still not this sprint's concern to push or
  review, per sprint 328's own note and this sprint's out-of-scope line, but
  the range keeps growing.
