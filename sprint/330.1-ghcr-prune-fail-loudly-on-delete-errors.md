# Make ghcr-prune fail loudly when deletions fail
**Difficulty:** 2

## Goal
`ghcr-prune.sh` reports only deletions that actually succeeded, and exits
non-zero when any DELETE fails — so a prune that removes nothing can never again
log success.

## Reason
The weekly prune has been reporting success while deleting **nothing**, for at
least eight consecutive logged runs. Its DELETE call is:

```bash
gh api --method DELETE "$BASE/packages/container/$encoded/versions/$id" --silent 2>/dev/null || true
```

`2>/dev/null || true` discards every failure, and the summary line then prints
the count of *selected* ids as though they were deleted. The `gh` token has
`write:packages` but not `delete:packages`, so every DELETE returns 403 —
confirmed during sprint 330, where a real, authorized prune of `develemail-api`
made 57 calls and all 57 returned 403 with no registry change.

The log proves it was never working: a keep-10 prune would report a roughly flat
number each week, but the claimed totals grow monotonically as the same backlog
is re-selected every Sunday —

```
2318 → 2423 → 2684 → 2806 → 2836 → 2886 → 2973 → 3006
```

— while `easyliving/api` sits at 423 versions. This silent failure is what made
the whole retention investigation necessary: it is why release 1174 still
existed at rank 15, and why nobody knew the prune had never run. A maintenance
job that cannot tell its operator it is doing nothing is worse than no job,
because it is trusted.

## Context

### The script
`scripts/ghcr-prune.sh` — after sprint 330 lands, the selection logic lives in
`scripts/lib/ghcr-prune-lib.sh` and the DELETE loop remains in the script. Read
the current loop before changing it; sprint 330 changed the surrounding code.

It runs from `~/Library/LaunchAgents/com.emit.ghcr-prune.plist`, logging to
`~/.local/log/ghcr-prune.log`. **That job is currently unloaded** (paused
2026-09-12 during sprint 330). Do not re-enable it.

### What "fail loudly" should mean
- Capture each DELETE's outcome instead of discarding it. Count successes and
  failures separately.
- The summary must report *deleted* (succeeded) and *failed* counts, never a
  selected count dressed up as deletions.
- Exit non-zero if any DELETE failed, so a scheduled run leaves a visible
  failure rather than a green log line.
- **Fail fast on an authorization error.** If the first DELETE returns 403 (or
  the response names a missing scope), stop that run immediately and print one
  clear line naming the likely cause — `delete:packages` — instead of issuing
  hundreds more requests that will all fail identically.
- Consider a cheap preflight: check `gh auth status` for `delete:packages`
  before selecting anything, and refuse to run (non-zero, clear message) when
  it is absent. `--dry-run` must still work without the scope.

### Testing without deleting anything
Do not make live DELETE calls to test this. Make the delete command injectable
(the repo's bash tests stub externals this way — see `scripts/lib/*.test.sh`)
and extend `scripts/lib/ghcr-prune.test.sh` (created by sprint 330) with a fake
that returns success, a fake that returns 403, and a mixed sequence.

### Conventions
Shell libs live in `scripts/lib/` with sibling `*.test.sh` files registered in
the root `package.json`'s `test:hooks`. There is no `check:affected` in this
repo; `pnpm test:hooks` is the suite.

## Tasks
1. Replace the error-swallowing DELETE with one that records success/failure
   per id.
2. Report deleted and failed counts separately in the per-package and final
   summary lines.
3. Exit non-zero when any DELETE fails.
4. On a 403 / missing-scope response, stop the run early and name
   `delete:packages` as the likely cause.
5. Add a preflight scope check that refuses a non-dry-run without
   `delete:packages`; keep `--dry-run` working without it.
6. Extend `scripts/lib/ghcr-prune.test.sh` with injected fakes covering all of
   the above. No live deletions.
7. Run `--dry-run` against the live registry to confirm nothing regressed.

## Completed

**Date:** 2026-09-12

### Summary
`ghcr-prune.sh` no longer discards DELETE failures with `|| true`. The DELETE
call and its per-id outcome now live in two new pure-ish functions in
`scripts/lib/ghcr-prune-lib.sh`: `_ghcrprune_delete_one` (issues one live
DELETE, returning 0 deleted / 2 auth-scope failure / 1 any other failure) and
`_ghcrprune_delete_ids` (loops ids through it, counting deleted vs. failed
separately and stopping immediately — without touching any remaining id — the
moment an auth-scope failure is seen). Splitting the actual `gh api` call into
its own named function is what makes it fake-able from the test file, the
same seam pattern `docker-build.test.sh` already uses for `docker`.

A preflight (`_ghcrprune_has_delete_scope`, parsing `gh auth status` text for
`delete:packages`) now runs before any other work whenever the script isn't
`--dry-run`, and refuses to start with a clear message naming the scope if
it's missing — verified live against today's real token, which has
`write:packages` but not `delete:packages` (sprint 330's finding): running
`bash scripts/ghcr-prune.sh` with no flags prints the refusal and exits 1
immediately, before even reading `.deploy-status.json` files. `--dry-run`
still completes normally without the scope (974 versions selected across all
10 packages, matching sprint 330's last recorded dry-run — no regression).

The script's summary line now reports `deleted` and `failed` as separate
counts (never a selected-count dressed up as deletions), and the script exits
non-zero if any DELETE failed or if an auth-scope stop occurred. No live
DELETE call was made at any point while building or testing this — the delete
loop is exercised entirely through fakes that override
`_ghcrprune_delete_one` in `ghcr-prune.test.sh`, and the only live `gh`
traffic during verification was the read-only `--dry-run` run and the
auth-status preflight check.

### Files changed
- `scripts/ghcr-prune.sh` — preflight scope check before any other work;
  DELETE loop replaced with a call to `_ghcrprune_delete_ids`, tracking
  `total_deleted`/`total_failed`, breaking out of the package loop on an
  auth-scope stop, and exiting non-zero on any failure
- `scripts/lib/ghcr-prune-lib.sh` — (new) `_ghcrprune_has_delete_scope`,
  `_ghcrprune_delete_one`, `_ghcrprune_delete_ids`
- `scripts/lib/ghcr-prune.test.sh` — fixture/fake-driven cases for all three
  new functions: no-scope text, scoped text, all-succeed, one ordinary
  failure, an auth-scope failure stopping the run early, and confirmation
  that ids after an auth-scope failure are never attempted
