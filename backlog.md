- `[design]` (found 2026-08-23, from emit-social sprint 34) **`migratePre` hardcodes the compose file it runs against instead of following the active/inactive slot.** `.emit-infra.json`'s `blueGreen.migratePre` is a raw shell string, passed through the CLI (`apps/cli/src/commands/deploy.ts:207`, `bg_migrate_pre`) into Ansible and `eval`'d verbatim by `blue-green-deploy.sh` (line 187). emit-social's value (and presumably any other `composeStructure: "separate"` project's) names one slot's compose file unconditionally — e.g. `docker-compose.blue.yml` — regardless of which slot `blue-green-deploy.sh` actually computes as `$INACTIVE` for this deploy. It only produces correct results today because every such project pins that compose file's image to the same tag (`:latest`) as the other slot's, so `docker compose run` resolves to the freshly-pulled image either way (the pull already happens before this step, per the 2026-07-21 fix noted at line 183-184 of the script). Pin either compose file to a differing tag/SHA and `migratePre` would silently run migrations against the wrong slot's image.
  **Fix sketch:** `blue-green-deploy.sh` already computes `$INACTIVE` before the migration step (line 185, after `compose_cmd_inactive` is defined at line 121) — the pieces needed are already in scope. Support a placeholder token in the `migratePre` string (e.g. literal `$INACTIVE` or `${INACTIVE}`) and substitute it with the real slot name immediately before `eval`, rather than relying on the config file's own `source`-time expansion (which would run too early — `ACTIVE`/`INACTIVE` aren't computed until after `CONFIG_FILE` is sourced, so reordering those two blocks is also needed, or the substitution must be an explicit `${MIGRATE_PRE//\$INACTIVE/$INACTIVE}` rather than implicit shell-source expansion). This removes the hardcoded-tag coincidence as a load-bearing assumption fleet-wide instead of requiring every project to remember it.
  **Scope:** touches `blue-green-deploy.sh` (ansible role, shared across the fleet) and the `.emit-infra.json` schema/docs for `migratePre` (documenting the new placeholder). Affects any project using `blueGreen.migratePre` with `composeStructure: "separate"` — worth an audit of which projects currently set `migratePre` before writing the sprint, since a syntax change to the string format needs every caller updated in lockstep. Not fixed here — this is a cross-fleet deploy-script change, out of scope for an emit-social sprint.
