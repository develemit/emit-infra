## Findings

### UI-01 · broken · "Last Deploy" reads "just now" for every project
**Pages:** /health (table + mobile cards) · **Seen:** all

`/status` returns `deployedAt` as a Unix-seconds string (`'1790047707'`); `deployAge()` (`app/health/helpers.ts:64`) does `new Date(deployedAt)`, which is Invalid Date, so the maths is NaN and it falls through to `'just now'`. Found by the orchestrator while verifying evidence; not in any track.

**Suggestion:** Parse numeric strings as seconds (`new Date(Number(s) * 1000)`) and return `'—'` on NaN; add a unit test with the real API shape.
**Evidence:** `fleet-health-health-real-desktop-light.png`

### UI-02 · broken · Destroy modal's Cancel/Continue can't be tapped on mobile
**Pages:** /projects/[name] (Destroy modal) · **Seen:** mobile

The modal's button row sits under the fixed bottom tab bar; `elementFromPoint` at the button resolves to the Ops nav link and a real click timed out. The most destructive action in the app can't be confirmed, or safely cancelled, by tapping.

**Suggestion:** Render the modal above the tab bar (z-index/portal) or pad it by the bar's height.
**Evidence:** `project-detail-test-smoke-destroy-modal-mobile-dark.png`, `project-detail-test-smoke-destroy-modal-mobile-after-click-dark.png`

### UI-03 · broken · Failed fetches render as legitimate empty (or healthy) states
**Pages:** /projects/[name]/admin, /networking, /storage, /logs, /data · **Seen:** unreachable project

One root cause across pages: API errors (503/404) are swallowed into empty results. Firewall shows **"Inactive · No rules configured"** and Cron shows "No cron jobs found" for a server that simply couldn't be reached (the firewall one is actively misleading). Networking's Response Times / Nginx / SSL / bandwidth panels render `null` and vanish. Storage shows "No tables found" for a 404 "postgres not configured". Live logs show a green **live** badge on a dead connection. The Backup panel doesn't render at all when no bucket is set.

**Suggestion:** Give the fetch helpers (`api-ops.ts` getCronJobs/getUfwRules and the networking/storage panels) an error state, and render "Couldn't reach server" / "Not configured" distinctly from "empty".
**Evidence:** `data-admin-testsmoke-admin-real-unreachable-desktop-dark.png`, `reliability-network-storage-test-smoke-networking-desktop-dark.png`, `reliability-network-storage-develemail-storage-desktop-dark.png`, `reliability-network-storage-test-smoke-storage-desktop-dark-before-prune.png`, `pipelines-logs-testsmoke-logs-error-desktop-dark-v2.png`, `data-admin-tastease-data-real-desktop-dark.png`

### UI-08 · broken · Delete backup removes the row before the request succeeds, with no error handling
**Pages:** /projects/[name]/data · **Seen:** backups present (stubbed)

Optimistic `setBackups(filter…)` then an un-caught `deleteBackup` → unhandled rejection; on failure the backup vanishes from the list with no message. Low reach today (no project has a bucket) but it's the delete path.

**Suggestion:** Await the DELETE, then remove; show an error and restore the row on failure.

### UI-09 · degraded · Deploy and Prune fire on a single click with no confirmation (and Deploy sends its POST twice)
**Pages:** /projects/[name], /projects/[name]/storage · **Seen:** all
