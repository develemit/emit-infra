# Opportunity Scan — emit-infra
**Date**: 2026-06-28
**Stack**: Next.js 15 App Router, Fastify, TypeScript, Nx monorepo, pnpm, Tailwind, Vitest
**Type**: Web app (infrastructure dashboard) + REST API + CLI

---

## Quick Wins
_Low effort, ship fast._

| Domain | Opportunity | Why it matters |
|--------|-------------|----------------|
| UX | Hardcoded "last seen 2h ago" in ProjectCard error state | Shows wrong timestamp, erodes trust in data freshness |
| UX | Ops "New conversation" button has no loading/confirm feedback | Silent session reset leaves users wondering if it worked |
| UX | Missing guided empty state on `/logs` page | No projects = blank page with no call to action |
| API | Add global auth middleware | Every route is fully unauthenticated — anyone reaching the API can trigger SSH, destroy infra, or read secrets |
| API | Validate & sanitize rollback `timestamp` and destroy body params | Malformed input reaches SSH commands with no schema check |
| API | Standardize error response shape across all routes | Mix of `{ error }`, raw strings, and `{ message }` makes client error handling fragile |
| Features | Toast/snackbar after destructive operations (rollback, restart, secrets sync) | Users complete actions with no confirmation it worked |
| Features | Fleet health / CI pages: add status filter (e.g. "show only failing") | Large fleet + no filter = scroll to find the problem |
| Features | Provision success — add "tail logs" / "check containers" next-step CTAs | Post-provision, users land with no guidance on what to verify |
| Perf | Retry with exponential backoff on critical fetches (ops session, status) | Transient failures cause immediate hard failures; one bad poll kills the view |
| Perf | Replace silent `.catch(() => null)` in use-disk-trend, use-memory-trend, projects.ts config read | Silent swallowing makes debugging why a chart stopped updating impossible |
| Perf | Validate backup-status JSON shape before use (add try/catch) | Corrupt `.backup-status.json` crashes the API endpoint for that project |
| DX | Add explicit return type annotations to async route handlers in ops.ts, projects.ts | Missing return types on exported async functions mask refactoring errors |
| DX | Configure vitest coverage thresholds in CI | Nothing prevents coverage from silently regressing to zero on new paths |

## Backlog
_Good ideas, lower urgency._

- **[UX]** No loading indicator when switching range hours on resource chart — charts briefly show stale data with no in-progress signal (`[name]/page.tsx` line 224)
- **[UX]** CI/Health/Logs pages have no first-run explainer — metric labels and color thresholds are undocumented for new users (`health/page.tsx`, `ci/page.tsx`)
- **[UX]** Deploy/CI timelines silently truncate long service names and commit messages without overflow indication (`deploy-timeline.tsx` line 101, `ci-timeline.tsx` line 100)
- **[API]** Status polling (30s cadence + 20s TTL cache) is a candidate for WebSocket/SSE subscriptions to eliminate client polling entirely (`projects.ts` status endpoint)
- **[API]** `/projects/:name/containers` and history endpoints return unbounded arrays; add offset/limit pagination for large fleets (`projects.ts` line 255, `history.ts` line 79)
- **[API]** Add request/response audit logging middleware for destructive operations — deploy, destroy, rollback all execute SSH commands with no centralized trail
- **[Features]** Ops chat: context banner only injects on first message; consider refreshing it when user selects a different project mid-session (`ops/page.tsx` line 141)
- **[Features]** Deploy/rollback/destroy modals show no retry button on SSH failure — user must close and re-initiate (`destroy-modal.tsx` line 204, `rollback-panel.tsx` line 99)
- **[Features]** Deploy markers on resource chart are rendered but not clickable — can't jump to deploy detail from a CPU spike (`resource-chart.tsx` line 145)
- **[Features]** Billing EUR→USD rate is a hardcoded constant (1.09); no export of monthly breakdown for accounting (`billing-widget.tsx` line 24)
- **[DX]** `projects/[name]/page.tsx` (321 lines) and `ops/page.tsx` (277 lines) mix state orchestration with render — extract `useProjectDetail()` and `useOpsChat()` hooks to enable unit testing
- **[DX]** No app-level README or SETUP.md; `NEXT_PUBLIC_API_URL` and `.env` patterns are undocumented — new developers must infer setup from code
- **[DX]** `container-table.tsx` (285 lines) and `full-chart.tsx` (252 lines) approach the 300-line cognitive load limit; split by presentation vs. data transform
- **[Perf]** HTTP check in status endpoint has a 5s timeout but no fallback status — if it hangs, `httpStatus` is null for the full 30s poll window (`projects.ts` line 33)
- **[Perf]** Five separate polling intervals across health/CI/project-detail/disk-trend/memory-trend overlap on data — consolidate with shared cache + exponential backoff on 503

## Already Strong
_Don't touch these — they're working well._

- **SplashGate boot sequence** — Accessible loading screen with progressive feedback, prefers-reduced-motion support, and intelligent event-driven dismissal. Well-structured.
- **Mobile/desktop responsive layout** — Consistent hidden/flex breakpoints, sticky headers, and table→card transforms on all pages. No reflow jank.
- **TTL cache + negative caching for SSH polling** — The 20s TTL below the 30s dashboard cadence prevents SSH command storms. Negative cache on failures is thoughtful.
- **Zod validation in push.ts and ops.ts** — Tight schemas with good error messages; the correct template for expanding to the rest of the API.
- **TypeScript strictness settings** — `strict: true`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess` at the monorepo root catch an entire class of bugs at compile time.
- **useEffect cleanup discipline** — setInterval and setTimeout cleanup is consistent across all custom hooks and pages; no memory leaks from recurring polls.
- **Modal-driven destructive flows** — Confirm-to-delete (type project name), SSE streaming terminal, and progressive disclosure pattern are all solid.
