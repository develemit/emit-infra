## High Impact
_Worth a dedicated sprint._

| Domain | Opportunity | Effort | Why it matters |
|--------|-------------|--------|----------------|
| Features | **Alert rules engine (configurable thresholds → push)** | high | Today alerts are binary up/down only. "Warn at disk >85%", "cert <30d", "backup stale >24h", "CPU sustained >75%" — rules stored per-project in config, evaluated by status-monitor, delivered via existing push.ts. This converts the dashboard from *viewing* problems to being *told* about them. |
| Features | **Incident annotation (root cause, notes, false-positive flag)** | med | Incidents are read-only; ops workflow wants "why did this happen" attached to each record. New `POST .../incidents/:ts/annotate` + extend `incident-panel.tsx`. |
| Features | **Fleet-level incident timeline (`/health/incidents`)** | med | Cross-project view correlating incidents with deploys/scale events — shows blast radius at a glance. |
| Perf | **Evict/TTL the `claude-session.ts` Map** | med | Unbounded session cache grows forever on a long-running API process. |
| DX | **Dashboard component test coverage (1/63 components tested)** | med | API routes are now well covered; UI has essentially none. Start with logic-heavy panels (health-card, incident-panel, full-chart-helpers pattern already proves the approach). |
| DX | **Unify vitest versions (dashboard ^4.1.8 / api ^3.2.6 / root ^3.0.0)** | med | Major-version divergence risks config/coverage behavior differences across packages. |

## Backlog
_Good ideas, lower urgency._

- **[API]** Container-logs and operations logs interpolate validated names into shell strings — regex already blocks injection, but passing as args (defense-in-depth) is cleaner (`container-logs.ts:31`, `operations.ts:213`)
- **[API]** Validate `config.domain` before building letsencrypt path (`projects.ts:192,198`)
- **[API]** secrets-sync base64 interpolation → prefer stdin/here-doc (`secrets-sync.ts:75`)
- **[API]** Standardize error response shape (`{ error }` vs `{ ok:false, error }`) across routes
- **[API]** Split monolithic 14-command status SSH call into independently cached probes — one dead subsystem no longer nulls the whole status
- **[Perf]** TTL cache can't distinguish "confirmed down" from "probe failed" — both cache null (`ttl-cache.ts`, `projects.ts:49-50`)
- **[Perf]** `readJsonl` loads full file into memory before tailing — stream or reverse-read (`lib/jsonl.ts:10-22`)
- **[Perf]** push.ts store cache never invalidates after add/remove subscription (`lib/push.ts:64-68`)
- **[Perf]** localStorage quota failures silently stop metric persistence (`metric-history.ts:57-59`)
