# Opportunity Scan — emit-infra
**Date**: 2026-07-02
**Stack**: Nx monorepo · Next.js 15 App Router · React 18 · TypeScript strict · Fastify API · JSONL persistence · SSH-based server probing
**Type**: Self-hosted infrastructure dashboard

---

## Quick Wins
_Low effort, ship fast._

| Domain | Opportunity | Why it matters |
|--------|-------------|----------------|
| API | **Container name validation in restart endpoint** | `req.params.container` passed to docker without sanitization — shell injection risk from malformed names (`projects.ts` ~line 258) |
| API | **Extract shared incident-pairing helper** | Down/up pairing logic is duplicated at `history.ts` lines 303–319 and 406–421; divergence risk and double maintenance |
| Performance | **Log errors in `status-monitor.ts` catch blocks** | `writeIncident()` swallows filesystem failures silently — lost incident records with no trace (`status-monitor.ts` line 26) |
| Performance | **Log errors in SSE stream catch in `container-log-viewer.tsx`** | Connection/network failures are silently swallowed — no way to debug why logs stop streaming (line 47–49) |
| Features | **Container restart confirmation dialog** | Restart fires immediately on click with no confirmation; a misclick on a production container causes instant downtime (`container-table.tsx` lines 58–73) |
| Features | **Scale advice chip → link to Settings panel** | "Upgrade to cx32" nudge appears but clicking does nothing; users must manually scroll to Settings to act on it (`health-card.tsx`) |
| UX | **Add `title` tooltip to truncated nginx endpoint paths** | Path column truncates at 260px with no hover tooltip — can't see full path on narrow screens (`nginx-endpoints-panel.tsx` line 43) |
| UX | **`aria-expanded` + `aria-label` on Settings collapsible** | Collapsible toggle button has no `aria-expanded` or `aria-label` — screen readers can't convey open/closed state (`project-settings-panel.tsx` line 95) |
| DX | **Add explicit return types to async fetch functions in `api.ts`** | ~20 functions use inferred return types, reducing IDE discoverability and making the API contract implicit (`api.ts` lines 186–350) |

## High Impact
_Worth a dedicated sprint._

| Domain | Opportunity | Effort | Why it matters |
|--------|-------------|--------|----------------|
| API / Performance | **JSONL read line limit — unbounded file reads** | med | Every history/metrics/incidents endpoint reads the full `.jsonl` into memory. Projects with years of history risk OOM + slow responses. (`history.ts` lines 84–400) |
| DX | **Split `api.ts` (645 lines) into domain modules** | high | Single file contains 60+ exported functions across 10+ domains — violates the ≤300 line target, high cognitive load, and hard to navigate. (`apps/dashboard/src/lib/api.ts`) |
| DX | **Test coverage for 17 untested API routes** | med | Only 3 of ~20 routes have tests. `billing`, `cert`, `cron`, `disk`, `nginx-endpoints`, `scale-advice`, `secrets`, `ufw`, and others have zero coverage for their core logic. |
| Features | **Complete the secrets sync flow end-to-end** | med | `SecretsPanel` shows drift but the in-panel "Refresh" only re-fetches. "Sync Secrets" is a separate header modal. Users see a problem but can't fix it without leaving context. (`secrets-panel.tsx`, `page.tsx`) |
| UX | **Mobile container empty state** | med | Desktop shows "No containers found" (line 84), but the mobile card section loops over `sorted` with no guard — renders silently empty on mobile when no containers exist. (`container-table.tsx` ~line 134) |

## Backlog
_Good ideas, lower urgency._

- **[API]** Missing Zod schema on `POST /projects/:name/register` body — accepts arbitrary config shape with no validation (`projects.ts` lines 74–90)
- **[API]** Inconsistent `nginx-endpoints` response shape — client handles `{ available: false }` vs `{ available: true, endpoints }` separately; could always return `{ endpoints: [] }` (`nginx-endpoints.ts`)
- **[API]** Container-restarts returns unbounded per-container arrays — unlike metrics there's no downsampling or limit (`history.ts` lines 272–279)
- **[Performance]** Frontend polling has no exponential backoff or jitter — all open tabs poll in sync every 30s (`use-project-detail.ts` lines 40–44)
- **[Performance]** HTTP health check probes have no circuit breaker — a slow failing URL can block the entire poll cycle (`status-monitor.ts` lines 81–104)
- **[Performance]** No SSH connection reuse across project polls — each cycle opens fresh SSH connections to every host (`status-monitor.ts`)
- **[Features]** Backup trigger has no completion polling — "Back up now" fires but user has no way to know when it finishes (`backup-panel.tsx` lines 107–116)
- **[Features]** Hardcoded deploy warning (80%) and backup age (24h/48h) thresholds — different projects have different tolerances (`page.tsx` line 90, `backup-panel.tsx`)
- **[DX]** CI runs all targets in parallel with `--parallel=3` — a lint failure could theoretically be masked by a faster-completing target (`ci.yml` line 45)
- **[DX]** Dashboard component test coverage sparse — only 2 test files for ~20+ components in `detail/` folder
- **[UX]** Settings panel has no client-side validation before save — invalid domain formats and malformed env keys only fail on the round-trip (`project-settings-panel.tsx`)
- **[UX]** Log page auto-follow has no "paused" indicator — no visual cue when user scrolls up and live-follow stops (`logs/page.tsx`)

## Already Strong
_Don't touch these — they're working well._

- **TTL cache design** — Stores both hits and negative (null) results; prevents SSH storm when servers go down and deduplicates concurrent callers automatically
- **TypeScript strictness** — `strict: true` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` across the whole monorepo; no `@ts-ignore` suppressions found in source
- **Existing API test patterns** — `history.test.ts`, `projects.test.ts`, `backup.test.ts` are thorough (300+ lines each), covering error cases and query param validation
- **Responsive design** — Consistent `lg:` breakpoint pattern throughout, desktop/mobile split without fixed-width breakage
- **Graceful degradation** — Detail page guards every optional section with null checks; nginx, cert, backups, SLA panels all appear only when data is available
- **Metrics downsampling** — 500-point cap before chart delivery is a smart bandwidth-vs-fidelity tradeoff
